Learn Open Source by Building Financial Indicators

Welcome to the official Contributor Guide & Documentation for NITJ's Finance Society Indicator Library. Here, you will learn the end-to-end Git & GitHub workflow used by software engineers and quant developers worldwide: from forking and branching, to writing pandas-based technical indicators, testing with pytest, and submitting production-ready Pull Requests (PRs).

Basics

What You Will Learn

By contributing an indicator to this repository, you will gain:

  • Real-world Git & GitHub mastery: Forking, upstream remotes, branching, commit hygiene, and handling Pull Request reviews.
  • Quantitative Finance experience: Understanding how market price series work and calculating real mathematical indicators (RSI, MACD, Bollinger Bands, ATR, etc.).
  • Python & Pandas skills: Writing vectorised data transformations and writing test suites with pytest.
  • A verifiable public portfolio item: Your commits and merged PRs will be publicly visible on your GitHub profile.

📊 The Raw Data Engine (`indicator_library.data`)

Every technical indicator needs historical price data to compute values. To ensure all indicators receive clean, consistent inputs, our library provides a centralized data engine powered by yfinance.

💡 The Pure OHLCV Guarantee
Standard Yahoo Finance downloads often contain extraneous columns like Dividends, Stock Splits, or Adj Close. Our module filters these out automatically, delivering strictly Open, High, Low, Close, Volume (OHLCV) data.

API Function: get_stock_data(...)

Also aliased as get_raw_ohlcv and get_raw_data.

Python 
from indicator_library import get_stock_data

# Fetch daily OHLCV data for any stock
df = get_stock_data(
    stock="AAPL",                  # Stock symbol (e.g., 'AAPL', 'RELIANCE.NS', 'TSLA')
    start_date="2024-01-01",        # Supports 'YYYY-MM-DD', datetime.date, or datetime
    end_date="2024-01-31",
    interval="1d",                 # '1d', '1h', '15m', etc.
    as_format="dataframe"          # 'dataframe' (default), 'records', 'dict', 'json'
)

print(df.head())

Accepted Date Formats

The start_date and end_date parameters are flexible and accept any of the following:

Format Example Usage
String (ISO / Standard) "2024-01-01" start_date="2024-01-01"
Python datetime.date datetime.date(2024, 1, 1) Ideal for dynamic calculations using timedelta
Tuple range date_range=("2024-01-01", "2024-01-31") Convenience parameter unpacking both dates
Pandas Timestamp pd.Timestamp("2024-01-01") Native pandas timestamp compatibility

Step 1

Fork & Clone the Repository

You cannot push directly to the main organization repository. Instead, you create a personal copy called a Fork.

  1. Go to financesociety-nitj/Indicator-Library on GitHub.
  2. Click the Fork button in the top-right corner. Keep the default settings and click Create fork.
  3. Now clone your fork to your laptop:
Terminal

git clone https://github.com/<your-username>/Indicator-Library.git
cd Indicator-Library

# Add the official repository as 'upstream' so you can sync updates later
git remote add upstream https://github.com/financesociety-nitj/Indicator-Library.git

# Verify remotes
git remote -v

Step 4

Implement Your Indicator (Case Study: RSI)

Let's walk through implementing the Relative Strength Index (RSI) indicator as a concrete example.

📐 The Math Behind RSI

1. Calculate day-to-day price differences: Δ = Close[t] - Close[t-1]

2. Separate into Gains (Δ if Δ > 0 else 0) and Losses (|Δ| if Δ < 0 else 0)

3. Calculate the rolling exponential/smoothed average of Gains and Losses over n periods (typically 14).

4. Compute Relative Strength: RS = AvgGain / AvgLoss

5. Compute RSI: RSI = 100 - (100 / (1 + RS))

Create a new file, for example indicator_library/rsi.py:

indicator_library/rsi.py 
"""
Relative Strength Index (RSI) Indicator Implementation.
"""

from typing import Union
import pandas as pd
import numpy as np


def calculate_rsi(
    data: pd.DataFrame,
    period: int = 14,
    price_col: str = "Close",
) -> pd.Series:
    """
    Calculate the Relative Strength Index (RSI) for a given OHLCV DataFrame.

    Parameters
    ----------
    data : pd.DataFrame
        OHLCV DataFrame containing at least the `price_col` (e.g. 'Close').
    period : int, default 14
        The lookback window for RSI calculation. Must be positive.
    price_col : str, default 'Close'
        The price column to use for calculations.

    Returns
    -------
    pd.Series
        Series containing the RSI values oscillating between 0 and 100.
    """
    if period <= 0:
        raise ValueError("period must be an integer greater than 0.")

    if price_col not in data.columns:
        raise ValueError(f"Required price column '{price_col}' missing from DataFrame.")

    # Calculate price change
    delta = data[price_col].diff()

    # Separate gains and losses
    gain = delta.clip(lower=0)
    loss = -delta.clip(upper=0)

    # Use exponential moving average (Wilder's Smoothing)
    avg_gain = gain.ewm(alpha=1 / period, min_periods=period, adjust=False).mean()
    avg_loss = loss.ewm(alpha=1 / period, min_periods=period, adjust=False).mean()

    # Calculate Relative Strength (RS)
    rs = avg_gain / avg_loss

    # Calculate RSI
    rsi = 100.0 - (100.0 / (1.0 + rs))

    # Where avg_loss == 0, RSI is 100
    rsi = rsi.where(avg_loss != 0, 100.0)
    # Where avg_gain == 0 and avg_loss == 0, RSI is 50
    rsi = rsi.where(~((avg_gain == 0) & (avg_loss == 0)), 50.0)

    rsi.name = f"RSI_{period}"
    return rsi

Step 5

Write Unit Tests with Pytest

No PR is merged without tests! Create a test file, e.g. tests/test_rsi.py, to verify calculations and handle edge cases:

tests/test_rsi.py 
import pytest
import pandas as pd
import numpy as np
from indicator_library.rsi import calculate_rsi


def test_rsi_bounds():
    # Synthetic steadily rising prices should yield RSI close to 100
    rising_prices = pd.DataFrame({"Close": [float(i) for i in range(1, 30)]})
    rsi = calculate_rsi(rising_prices, period=14)

    # Valid values must be between 0 and 100
    valid_rsi = rsi.dropna()
    assert (valid_rsi >= 0).all() and (valid_rsi <= 100).all()
    # After consecutive gains, RSI should be high (> 90)
    assert valid_rsi.iloc[-1] > 90


def test_rsi_invalid_period():
    df = pd.DataFrame({"Close": [10.0, 11.0, 12.0]})
    with pytest.raises(ValueError, match="period must be"):
        calculate_rsi(df, period=0)


def test_rsi_missing_column():
    df = pd.DataFrame({"Open": [10.0, 11.0, 12.0]})
    with pytest.raises(ValueError, match="Required price column"):
        calculate_rsi(df, price_col="Close")

Run your tests locally and make sure everything passes:

Terminal 
# Run all tests
pytest

# Run only your new test file with verbose output
pytest tests/test_rsi.py -v

Automated CI Checks (GitHub Actions)

As soon as your PR is submitted, our automated Continuous Integration (CI) workflow triggers automatically. You will see a box near the bottom of your PR page listing running checks:

Job Name Runner OS Purpose Expected Status

✅ Green Means Ready for Review
When all 4 checkmarks turn green ("All checks have passed"), your PR is verified and ready for the Finance Society maintainers to review and merge into the codebase!
❌ What if a CI Check Fails?
Don't worry! Fixing test failures is a core part of real-world development:
  1. Click the Details link next to the red failing job.
  2. Read the pytest output and traceback to find which test assertion failed.
  3. Fix the bug locally in your editor and re-run pytest on your laptop.
  4. Commit and push the fix: git commit -am "fix: resolve test assertion" && git push
  5. GitHub Actions will automatically restart and re-run all checks on your updated code!

FAQ

Review Tips & Common Pitfalls

  • Never mutate inputs: Do not do data['rsi'] = ... on the argument passed in. Always do df = data.copy() or compute standalone Series.
  • Check your git config: Ensure your Git email matches your GitHub account so commits show up on your profile.
  • Keep PRs focused: One indicator per PR. Don't bundle 5 different indicators in a single PR. Small, clean PRs get reviewed and merged quickly.
  • Sync with upstream: If other people's PRs were merged, run git pull upstream main on your main branch to stay updated!
